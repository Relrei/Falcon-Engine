## 0. 実際の症状(車のレンダー。DLSS 6spp)

フロントガラス・サイドガラス・奥の車のリアガラスに、黒い**粒状のノイズが全面に残っています**。
ボディや床は綺麗に収束しており、ガラスだけが弱いという状態です。比較用の 2 枚目(ガラスが滑らか)と並べると、差はガラスの領域に限られます。

これは、下の仮説 2 と整合します。**RR は、鏡(粗さ 0・specular albedo ≒ 1)の画素のノイズを、鏡像の細部として残します**。
ボディのように拡散面に見えていれば、同じ spp でも強く除去されます。ガラスの向こうの内装は、ガラスを通した光でしか照らされないので、
6spp では特にノイズが大きくなり、それが「鏡の細部」として保たれている、という読みです。

## 1. 現状の実装(コードから)

- ガラスのガイドは「ガラス面そのもの」です。DLSS では `follow_reflections` を切っているため(`sync.cpp` の DLSS 判定の箇所)、
  最初の交点の値を全サンプルが書きます。
  - 法線・深度・モーション: ガラス面のもの。
  - 粗さ 0、specular albedo ≒ 1、diffuse albedo 0。
  - CPU ハーネスで実際に確認しました: クリアガラスのガイドは `spec=(1,1,1) diffuse=(0,0,0) rough=0` で、RR からは完全な鏡に見えます。
- 屈折の先は追いません。PSR(完全鏡面を仮想像で置き換える実験。`FALCON_DLSS_PSR`)も、屈折は明示的に除外しています。
- specular hit distance は、「一次バウンスが glossy だったサンプル」だけが書きます(`bounce == 1 && glossy_bounce == 1`)。
  - ガラスの鏡面**反射**は `glossy_bounce` に数えられます(`path_state_next`)。
  - ガラスの**屈折**は `transmission_bounce` で、書きません。
  - 前処理は、書いたサンプル数で平均します。1 つも無いピクセルは 0(= ヒットなし)です。
- DLSS のモーション入力は、通常の `PASS_MOTION`(Vector パス)です。データパスは、最初の非透明ヒット(= ガラス面)で書かれます。

## 2. 公式ガイドの該当箇所(DLSS-RR Integration Guide。要約)

| 節 | 内容 |
|---|---|
| 3.4.1 Diffuse Albedo | 透明面の色が支配的なピクセル(反射の強い窓・水面)では、アルベド・法線・粗さを透明面の値へ**ブレンド**するとよい。背景の信号を弱め、反射の上に背景の細部を再構成しにくくする。鏡面モーションを渡さない場合は、depth・法線・specular hit distance を、**背景か透明面のどちらかに揃える**(アルベドと粗さはブレンドしてよい)。 |
| 3.4.8 / 3.4.9 | 窓の反射は、透明面基準の鏡面モーションか、透明面基準の depth・法線・hit distance で改善する。hit distance は「一次面を起点にした鏡面レイの距離」の定義。 |
| 3.5 Noisy guide buffers | 屈折でガイドがノイズになる(光線追跡の粗い屈折など)なら、屈折面のアルベド・法線・粗さは**定数**のほうが、滑らかに収束する。ガイドのノイズは、粒状やゴーストの原因になる。 |
| 屈折の扱い(3.5 付近) | 屈折した背景のモーションを正しく出すのは難しい。「背景のモーションで代用するのは、不完全だが妥当」とされている。 |
| 3.4.11 Color Before Transparency | 粒子など、後から重ねた透明物のゴースト対策。ガラス越しの背景の再構成を直接扱うものではない。 |

ガラス・屈折の扱いを詳しく書いた節は、ガイドにはほぼありません。

## 3. 原因の仮説(未検証)

1. **ちらつき**: ガラス画素の hit distance が、そのフレームで反射サンプルを引いたかどうかで、0 と「反射先の距離」のあいだを行き来する。
   RR が作る鏡面モーションが不安定になり、少ない spp で特にちらつく。
2. **ガラス越しの背景がぼける**: ガイドが「鏡」で、背景の情報(アルベド・法線)が RR に渡っていない。RR が、背景の細部をノイズと見なして平滑化する。
3. **動かすと、ガラス越しの絵が尾を引く**: 屈折した背景を、ガラス面のモーションで追っている(視差の分がずれる)。

## 4. 実装(v1): ガラス越しガイド

`FALCON_DLSS_GLASS_THROUGH=1` の時だけ、鋭い(delta の)ガラス・屈折クロージャが一次バウンスにある画素で、次のようにガイドを書きます。

1. ガイドは BSDF サンプリングの**前**に書かれるので、鋭いガラスの最初の交点では、**書かずに保留**します(`PATH_RAY_GLASS_PENDING`)。
2. BSDF のローブが決まった**直後**(`integrate_surface_bsdf_bssrdf_bounce`)に解決します(`film_write_denoising_glass_resolve`)。
   - **屈折**したサンプル: その場では何も書かず、次の面(背景)が書きます(`PATH_RAY_GLASS_THROUGH`)。
     背景の面は、深度(カメラ深度の絶対値)・法線・アルベド・粗さ・specular albedo を、最初の交点と同じ形で書きます。
     ガラスの色味は、ガイドのスループットに掛けます(混合クロージャの時は、選ばれた確率の分を割り戻します)。
   - **反射**したサンプル(と、ガラス以外のローブ): ガラス面のガイドを、その場で書きます。
3. ローブは Fresnel に比例して選ばれるので、ピクセルの平均は、公式 3.4.1 が言う「反射の強さに応じたブレンド」になります。
4. ガラスから始まった経路(`PATH_RAY_GLASS_SEEN`)は、specular hit distance を書きません(ちらつきの元を止め、公式の「揃える」に従う)。
5. 屈折して空に抜けたサンプルは、カメラから空を直接見た時と同じ、遠い深度を書きます。
6. ガラスの先が、別のガラスの面(瓶の向こう側の壁など)なら、そこでも保留に戻します(連鎖)。

### マット・モード(`FALCON_DLSS_GLASS_THROUGH=2`、両方なら 3)

公式 3.5(ノイズになるガイドは、定数のほうが滑らかに収束する)に沿って、ガラス面**自身**のガイドを、定数の拡散面にします。

- diffuse albedo は 0.5 の定数、specular albedo は 0、粗さは 1(法線・深度は、ガラス面のまま)。
- モード 2 では、鋭いガラスの最初の交点で、そのままこの値を書きます。
- モード 3 では、反射したサンプルがこの値を書き、屈折したサンプルは背景のガイドを書きます。
- ガラスの経路は、specular hit distance を書きません。
- 犠牲になるもの: ガラス面の反射(空の映り込みの筋など)が、RR には拡散面に見えるので、鋭さが落ちます。

対象外(従来どおりの挙動): 粗いガラス、透明(アルファ)成分を含む混合、ガラスが半分未満の混合、`FALCON_DLSS_FOLLOW_REFLECTIONS` が有効な時、PSR の経路。

変更したファイル: `kernel/film/denoising_passes.h`(本体)、`kernel/integrator/shade_surface.h`(解決の呼び出し)、
`kernel/types.h`(フラグ)、`scene/film.h` / `film.cpp`(ソケットとカーネルのフラグ)、`blender/sync.cpp`(環境変数)。
新しいパス(レンダーバッファの増加)は**ありません**。

## 6. 検証ハーネス

`docs/dlss-glass/run_harness.sh`(clang++ だけ要ります。Blender のビルドは不要)。
Cycles の CPU カーネルをそのまま取り込み、合成した交点と BSDF クロージャで、次を確かめます。

- 保留 → 反射で解決(ガラス面のガイド) / 屈折で解決(背景が書く) の流れ、フラグの遷移。
- 背景は絶対深度・法線・アルベドで書かれ、その後は何も書かれない。
- 色付きガラスは、色味だけがアルベドに乗る(単一クロージャで 1 を超えない)。混合クロージャで、混合の割合が二重に掛からない。
- ガラス → ガラス(連鎖)、ガラス → 空、粗いガラス、追従有効、拡散面の初回ヒットに影響しない。
- ガラスの経路で hit distance が書かれない。
- 粗さがわずかにあるガラスは、`FALCON_DLSS_GLASS_ROUGH` の段階(0〜3)に応じて、対象になる / ならない。
- ノブがオフなら従来どおり。マット・モード(単独 / ガラス越しとの併用)、拡散面・粗いガラス・追従有効への非影響。

実行結果は「ALL PASSED」です。これは**ロジックの確認**で、絵の良し悪しは実機の A/B で見ます。

## 7. 既知の制限・リスク

1. **ガイドの抽選ノイズ**: 反射と屈折のどちらを引くかは、サンプルごとの抽選です。1 ピクセルの平均は Fresnel のブレンドになりますが、
   spp が少ないと、ガイドが二項分布のばらつきでざらつきます(公式 3.5 の「ノイズのあるガイドは粒状・ゴーストの原因」)。
   ビューポート・1spp のストリームで特に注意してください。数え上げで平均する形(専用パスと前処理での混合)にすれば無くせますが、パスの追加が必要です(v3)。
2. **モーションはガラス面のまま**: 仮説 3 は、まだ扱っていません(v2)。背景のガイド + ガラス面のモーションの組み合わせが、かえって悪く見える可能性があります。
3. **背景のガイドは、実際の物体の位置**です。屈折で歪んだ像の位置ではありません(公式 3.5 の「屈折した像に合わせたガイド」の近似)。
4. 保留した後、BSDF のサンプリングが失敗して早期に戻った経路は、その 1 サンプルのガイドが書かれません(頻度は小さい)。
5. 空へ抜けた屈折サンプルが 1 つでもあると、深度は遠い値で上書きされます(既存の空の扱いと同じ)。
6. Metal / oneAPI / HIP: 追加の関数は他のバックエンドでも使える書き方にしましたが、コンパイルしていません。
7. **ガラスの判定は「粗さがほぼ 0」**です(既定)。わずかでも粗さのあるガラスは対象外になります。`FALCON_DLSS_GLASS_ROUGH` で許容度を上げられますが、粗いガラスでは屈折の先がぼやけて、モード 1 のガイドがざらつきやすくなります(その場合は `=2` / `=3` が向く)。

## 9. 検討した案(実装していない)

### OIDN との併用

| 案 | 内容 | 見立て |
|---|---|---|
| A. OIDN で先に denoise → DLSS へ | ノイズ画像の代わりに、OIDN 済みの画像を RR に入れる | RR はノイズ入力を前提にしている。平滑すぎる入力は、細部の消失やゴーストの元になり得る。全体にかけるのは危険(公式ガイドにも、極端な場合の事前 denoise の記述はあるが、完璧でなくてよいとある) |
| B. ガラス領域だけ OIDN に置き換える | DLSS の出力を、ガラスのマスクで OIDN の結果とブレンドする | 今回の症状には素直に効くが、OIDN は時間方向の安定性を持たないので、アニメではガラスだけちらつく可能性がある。アップスケールとの併用では、ガラス部分だけ解像度が落ちる |
| C. OIDN でガイドを前処理する | OIDN の prefilter で、アルベド・法線のノイズを除いてから RR に渡す | `=1` の弱点(ガイドの抽選ノイズ)を消せる。RR の時間安定性はそのまま使える。公式 3.5 にも沿う |

先に確認できること: DLSS のガイドをダンプ(`FALCON_DLSS_GUIDE_DUMP`)して OIDN で同じ画像を処理し、OIDN が 6spp のガラスをきれいに処理できるかを見る。

### ガラスを別の「面」にして、RR を面ごとに通す(DLSS ベースの新しい手法)

NVIDIA の「stable planes」に近い考え方です。

- 面 A: 不透明な物と、ガラス面の反射。面 B: ガラスを通して見えるもの(屈折した背景)。
- 面ごとに、専用のカラーとガイド(背景の法線・アルベド・動き)を作って RR に通し、反射/屈折の割合で混ぜる。
- 面 B のガイドは決定的な値で、抽選ノイズが入らない。RR は面ごとに履歴を持つので、時間方向も安定する。背景の動きも面 B に渡せる(v2 を含む)。
- 必要なもの: 面 B 用のパス、RR を複数回呼べる denoiser(Shadow Catcher で、追加の RR を通す仕組みは既にある)。コストは、ガラスがあるシーンで RR が約 2 回。

### 経路の分岐(反射と屈折を毎回両方追う)

ガラスの最初の交点で、反射と屈折の**両方の経路**を毎回追い、Fresnel の重みで合成する。
Cycles には、Shadow Catcher で経路を 2 本に分ける仕組み(`integrator_split_shadow_catcher`)があり、参考にできる。

- 反射側の画像が、6spp でもほぼ空にならない(反射は全体の 5〜10% しか抽選で選ばれないため)。ノイズ自体も減る。
- ガラス画素だけ、経路が約 2 倍になる。カーネルの大改造で、実機でのテストが必須。

車のフロントガラスは、屈折が支配的です。今回の症状には、まず `=1` / `=2` / `=3` で足りる可能性があります。
反射も強いガラス(ショーウィンドウ、水面)では、上の「面に分ける案」「経路の分岐」が効いてきます。
