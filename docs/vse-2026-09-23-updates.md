# VSE アップデート (2026-09-23)

Falcon Engine の Video Sequence Editor(VSE)へ、今回まとめて追加した機能です。
どれも Falcon Engine のビルドを起動すればそのまま使えます(追加のインストール操作は不要)。

## 1. ヘッダーの表示切り替え

今まで `ビュー` / `プロキシ` メニューの奥にしかなく気付きにくかった4つの設定を、
ヘッダーに常時表示のボタン・欄として出しました。

左から: **時計アイコン**(秒/フレーム表示切替)・**チャンネル欄アイコン**(左パネルの開閉)・
**プレビュー解像度**(既定 Scene)・**チャンネル番号**(既定 0・この番号以下だけ表示)。

### 手順: 秒/フレーム表示

1. ヘッダーの時計アイコンをクリックする
2. 現在フレームの表示(左上の欄)が `1` → `0+01`(タイムコード形式)のように切り替わる

### 手順: チャンネル欄の開閉

1. ヘッダーのチャンネル欄アイコンをクリックする
2. 左側にチャンネルの一覧パネルが出入りする

## 2. チャンネルの前後入れ替え

左のチャンネル一覧パネル(上の①で開閉)の各行に、上下の矢印ボタンを追加しました。

### 手順

1. チャンネル一覧パネルを開く(上記参照)
2. 入れ替えたいチャンネルの行にある ▲ または ▼ を押す
3. 隣のチャンネルとストリップの中身がまるごと交換される(時間位置はそのまま)

実機で「チャンネル1(教室の映像)」と「チャンネル2(テキスト)」を入れ替えると、
チャンネル1にあった映像がチャンネル2へ、チャンネル2にあったテキストがチャンネル1へ、
中身ごと入れ替わります。Blender の仕様上チャンネル番号が大きいほど
手前(上)に表示されるので、この操作で「どちらを手前に出すか」をドラッグ&ドロップなしで
切り替えられます。矢印は常に画面の上/下を指すので、チャンネル並びを反転している場合
(上下反転ボタン)でも迷わず使えます。

## 3. プレビューでハンドルをドラッグしてクロップ(BL Easy Crop)

サードパーティ製アドオン **[BL Easy Crop](https://github.com/usrname0/BL_EasyCrop)**
(作者: usrname0、GNU General Public License v3.0 or later)を同梱し、既定で有効にしました。

### 手順

1. プレビューでクロップしたいストリップを選択
2. `Shift + C` を押す(または左のツールバーからクロップツールを選択)
3. 表示されたハンドルをドラッグして範囲を決める

クロップした分だけ左右・上下が透明(市松模様)になり、画が縮みます。
今までの「数値を4つ手入力する」クロップに比べて、ハンドルを直接ドラッグできる分、
直感的に調整できます。

## 4. 追加した映像のプロキシを自動で作る(16bit の画像連番の修正)

以前から入っていた「VSE Proxy Helper」(プレビュー用に軽いプロキシを自動生成する仕組み)が、
**16bit の画像連番(PNG など)に対して正しく動くように修正**しました。

### 手順

1. 編集の最初に、サイドバー `Strip > Proxy Settings` から
   **「Set Up Proxies for Playback」**を1回押す
2. 以降にタイムラインへ追加した動画・画像連番は、裏で自動的に軽量プロキシが作られる
   (`プロキシ` という言葉を意識する必要はありません)

### 証拠: 直す前後の実際のファイル

直す前は、16bit の PNG から作ったプロキシが意図しない形式(EXR・float)で焼かれ、
サイズも速度も改善しませんでした。直した後、実機で 16bit PNG 連番のプロキシを
実際に焼いて確認した結果:

```
$ file BL_proxy/images/100/0001.png_proxy.jpg
0001.png_proxy.jpg: JPEG image data, ... precision 8, 1920x1080, components 3
```

`precision 8` = 8bit の JPEG として正しく焼けています(直す前は float の EXR になっていました)。
これで 16bit の画像連番でも、最初に 1 回設定すれば、あとから追加した素材にもプロキシが自動で作られます。再生の軽さは素材と機械によって変わります。

## 5. 再生中に不具合が起きないための修正

- 再生中に Python から Strip を削除すると落ちる不具合を修正
- 再生開始直後に Strip 側の GPU 再生パスが正しく使われず、CPU 使用率だけ上がる不具合を修正

いずれも実機で複数回の動作確認済みです。詳しい経緯は
[Issue #10](https://github.com/Relrei/Falcon-Engine/issues/10) を参照してください。
