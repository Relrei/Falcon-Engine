## 直した内容

### 切っただけの書き出し(fast path。既定 ON)
通常の書き出しと違う動画を、警告なしに出していた件です。

- `strip_fastpath.cc`: ハード分割・トリムした素材が、素材の頭から書き出される(`anim_startofs` を足していなかった)。通常の描画と同じ式(`give_frame_index` + `anim_startofs`)で決めるようにした。
- `strip_fastpath.cc`: 速度変更(キー 2 本の retiming)を「切っただけ」と見なしていた。retiming があれば通常経路へ回す。
- `strip_fastpath.cc`: ハンドルを素材の外へ引いた(ホールド)ストリップを通していた。通常経路へ回す。
- `pipeline.cc` / `strip_fastpath.cc`: 範囲がシーンの `sfra/efra` で、`RE_RenderAnim` の引数を見ていなかった(`-f N`・操作のフレーム範囲)。引数の範囲と刻みを渡す。範囲の頭がシーン開始と違い、音がある時は通常経路へ回す。
- `strip_fastpath.cc`: スタンプの焼き込み・デインターレース・浮動小数化・色空間の変換を通していた。通常経路へ回す。
- `movie_fastpath.cc`: `int(frs_sec_base)` で 1.001 が 1 に切り捨てられ、29.97 / 23.976 / 59.94 fps が 30 / 24 / 60 fps として出て、音とずれていた。通常の書き出しと同じ time base(`calc_time_base` の写し)にした。
- `movie_fastpath.cc`: 先頭・末尾の焼き直しが 200 kbit/s に固定されていた(`b:v` は `AVCodecContext` の option ではない)。`bit_rate = 0` にした。
- `movie_fastpath.cc`: 音声の符号化器を出し切っておらず、末尾が欠けていた。符号化器と緩衝も解放していなかった。
- `movie_fastpath.cc`: 「出力の大きさが違う」のメッセージが、解放済みの `codecpar` を読んでいた(UAF)。

### レンダーパイプライン
- `pipeline.cc`: 非同期保存で、PNG / JPEG に `Saved:` のログが出ず、errno も失われていた(レンダーファームのスクリプトがこの行を読む)。
- `pipeline.cc`: 遅延した `render_write` が次のコマの `cfra` で呼ばれていた。書いたコマの `cfra` に戻して呼ぶ。
- `pipeline.cc`: VSE のシーンストリップの入れ子レンダーが、毎コマ malloc を OS へ返していた。報告先を持つ(利用者が始めた)レンダーだけ数える。

### 映像の読み込み・書き出し
- `movie_write.cc`: NVENC が Lossless と CBR でも使われていた。H.265 10bit の可逆は CPU にも落ちず失敗し、8bit の可逆は cq の VBR になっていた。使わない。実際の open で GPU が落ちた時は、同じ stream で CPU の符号化器へやり直す。
- `movie_read.cc`: CUDA があると、NVDEC が使われない映像(libdav1d、アルファ付き VP9、10bit / 4:2:2 の H.264)まで 1 スレッドにしていた。NVDEC が実際に使われ得る映像だけにする。

### CUDA 以外のビルド
- `WITH_FALCON_SHARC` が CUDA のカーネルにしか渡っておらず、HIP / HIP-RT / oneAPI / Metal ではコンパイルできず、`KernelIntegrator` の配置もホストと食い違っていた。全バックエンドへ渡す。
- `DeviceKernel` の DLSS 用の 3 カーネルは CUDA にしか無いのに、HIP が全値を読み込んでエラーにしていた(AMD で起動できない)。`device_kernel_is_cuda_only()` で飛ばす。
- CUDA 無しの `WITH_DLSS=ON` はコンパイルできない。警告を出して OFF にする。
- `WITH_FALCON_SHARC=OFF` で `shade_surface.h` がコンパイルできない。`falcon_*` の読み取りを囲った。

### Cycles カーネル
- SHARC の早期終了が、深度・法線・Position・ノイズ除去ガイドの書き込みとホールドアウトを飛ばしていた。終了を直接光の直前まで遅らせた。ブレンドにパスの throughput を掛け、ホールドアウトと通過するだけのヒット、光子パス中は使わない。
- 光子パスで、透明 BSDF だけのヒット(切り抜きの葉・穴)が光子を止めていた。
- 光子パスで、太陽光への放射を発射画素へ書き込み、ホタルになっていた。
- CPU の光子パスで、捨てられた光子 1 個で残りの全サンプルが打ち切られ、暗くなっていた。
- `falcon_lt_splat_px` が、Combined 無効やボーダー・マルチデバイスで範囲外へ書いていた。`PASS_UNUSED` を守り、全フレーム単一バッファでない時はライトトレースを実行しない。
- `FALCON_PHOTON_CONTACT_RADIUS` の上限をホストと同じ 8 セルにした。
- 光子ポイントの 27 近傍の集計で、同じスロットを重複して数えていた。

### Cycles ホスト側
- `session.cpp`: ESC で中断した時に、途中結果の書き出しが飛んでいた(`get_cancel()` を `get_error()` に)。
- `session.cpp`: DLSS 以外のレンダーでも、`Session::reset` がピクセルジッターを固定していた。
- `integrator.cpp`: DLSS がジッターを強制するため、毎バッチ `device_update` が全部走り、光子ベイクの SHARC・カウンタを毎回ゼロ埋めしていた。ジッターだけの更新では Falcon のブロックを飛ばす。光子系のバッファ(約 480 MB)を、使わなくなったら解放する。
- `render_scheduler.cpp` / `path_trace.cpp`: DLSS のプリロール・ストリームの不具合(適応サンプリング ON で毎パス同じサンプル、後処理と最終書き出しが飛ぶ、適応フィルタの位置ずれ、ストリームの完了が 1 バッチ遅れる、再生切り替えでバッファの解像度が変わる)。`PathTrace::cancel()` を本家の挙動に戻した。
- `sync.cpp`: ビューポートの既定「自動」ノイズ除去が DLSS に解決されても、first-surface ガイドなどが効かなかった。積分器の解決済みの状態を見る。
- `sync.cpp`: SHARC の Warmup / Live が必要とするパスが、ビューポートでは追加されず、何も起きなかった。
- `session.cpp`(Blender 側): カット検出の camera / frame が全セッションで共有され、競合していた。最終のアニメ書き出しだけをプロセス共有にし、それ以外はセッションごとにした。DLSS 履歴の「暖まった」印も、アニメ書き出しだけが立てる。
- `camera.cpp`: Render Region がある時の固定サイズの高さ。
- `sync.cpp`: `falcon_das_map` / `falcon_error_map` の `//` 相対パス。
- `device.cpp`: CPU のみ選択・GPU 全オフを、GPU に変えていた「安全網」。OptiX→CUDA の格下げで何も見つからない時だけにした。

### DLSS
- Shadow Catcher があるシーンで、`PASS_COMBINED` 以外が `false` で返り、ノイズ除去全体が失敗扱いになっていた。色画像として RR に通す。
- `mbstowcs` が `-1` を返した時の例外、「未対応」結果のキャッシュ、Windows の `NGXPath` の長さ、`NGXDriver::init` の競合、`multi_devices`、Emission パスでエミッシブガイドが有効になる件。
- `falcon_plugins.py`: manifest が UTF-16 や `id` が配列だと、`scan()` 全体が落ち、DLSS のアドオンが出なかった。

### VSE
- GPU プレビューの輪の錠を持ったまま先読みを起こし直し、自分で自分を待つデッドロック(Undo 後の再描画で固まる)。
- 8bit へ落とす判定が `render == nullptr` で、`render.opengl(sequencer=True)` の出力まで 8bit になっていた。
- 反転(FLIPX/Y)のストリップが GPU プレビューで反転しない。コンポジターのモディファイアがある時の変形順。
- キャッシュの重複除去が、錠を離した後に借りた `ImBuf` を読んでいた。
- GPU 経路が動画の読み手を閉じない。空きメモリが少ない時に先読みが止まらない。GPU プレビューの先読みの窓が実質 3 コマだった。
- 層の転送失敗で `ImBuf` を漏らし、層が欠けた 1 コマを返していた。YUV シェーダの初期化の競合。
- GPU 再生 ON で、波形・パレード・ベクトルスコープ・ゼブラ・メタデータが出ない。
- チャンネル入れ替えがロックを見ず、depsgraph も更新しない。
- ファイルブラウザの連番: 展開でサブフォルダが二重になる、まとめがフォルダを無視する、削除が先頭 1 枚だけ、改名は連番のままだと拒否する、検索が先頭のコマ名だけ、描画のたびに全コマ分のパスを作る。
- プロパティを持たないシーンで、チャンネル反転が前のシーンの値のまま残る。反転表示で上端の余白が足りない。

### アドオン(Python)
- 光子ベイクが失敗すると `FALCON_PHOTON_MODE=bake` が残り、以後の F12 やビューポートが全部ベイクになっていた(開始前の状態を控えて戻す)。

## 判断を含めた変更(確認してほしい点)

1. NVENC を **CBR にも使わない**(依頼は Lossless の除外だけ)。Lossless だけに絞るなら、`movie_write.cc` の `hw_quality_ok` の `>` を `!=` にする。
2. ライトトレースのビューティで、焼いた光子(add)を足さない(集光の二重加算の回避)。ボーダー・マルチデバイスではライトトレースを実行しない。
3. Shadow Catcher があるシーンは、DLSS の時間蓄積を失い、更新ごとの評価が 3 回になる。別のインスタンスを持てば避けられるが、GPU メモリが増える。
4. エンジン VSE で Scene タブのパネルを消すため、パネルを再登録している。他のアドオンのパネルの後ろに回り、開閉状態が戻る。
5. `__del__` の明示呼び出しを Cycles だけにした。
6. fast path は、範囲の頭がシーン開始と違い、音がある時は通常の書き出しへ回す。

## 直さなかった項目(設計判断のため)

- `versioning_520.cc:922`: サブバージョン 45 でビット(旧「NVENC を使う」)の意味が反転する件。直すには新しいサブバージョン(46)が必要で、上流の更新とぶつかる。過去に旧来の意味で保存した 502.45 のファイルがあるかで判断が変わる。
- `mnee.h`: フラットシェードのキャスターを MNEE が受け付ける件。意図的と判断したが、Shadow Caustics が ON の時は本家と絵が変わる。
- `falcon_sharc_cell` の既定(0.05 と 0.2)、`falcon_error_cell` が使われていない件。
- 環境変数の「OFF」の書式が、コンポーネントごとに不統一な件(`FALCON_VSE_CHANNELS` は `off` で切れない)。
- warm-up フレームで `render_pre` / `render_post` が負のフレーム番号で呼ばれる件(DLSS のみ)。
- 非同期保存で、`render_post` がファイルの書き込み完了前に走る順序の差。
- operators.py のキャッシュ名が blend のファイル名だけで決まる件と、光子の add 状態がプロセス全体で共有される件。

## 残っている既知のリスク

- fast path: 素材の実際のデコード可能な長さを確認していない。`streamindex != 0` と `SEQ_USE_VIEWS` は弾いていない。音声の `out_frame + 1` の追加送出が残っていて、通常より最大 1 コマ分長くなり得る。
- 光子ベイクの add モードで、SHARC と共有する `FALCON_SHARC_CACHE` の衝突は残っている。
- NVDEC の判定は予測で、`get_format` で拒否される映像は 1 スレッドのままになり得る。
- ffprobe / nvidia-smi の同期実行は、タイムアウト(10 秒 / 4 秒)まで UI を止め得る(結果はキャッシュする)。
- 範囲書き出しの子の、コンポジターの File Output ノードの `//` パスは、一時コピー基準のまま。
- 新しいエラー文言は `falcon_i18n.py` に無く、英語のまま出る。
